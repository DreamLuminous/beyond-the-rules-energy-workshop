# 规则之外 · 能源工坊

本机运行的五关规则游戏。新手篇练习顺序、循环与颜色条件；第二章练习数组遍历与函数。每关可选自然语言、伪代码或 C 代码，使用相同的地图、目标和本地判定。

## 启动

Windows 可双击“启动游戏.cmd”，会启动本机服务并打开浏览器。游玩时保留服务窗口；如果默认的 4173 端口已被其他程序占用，启动器会自动选择 4174—4183 中的可用端口并打开正确页面。不要直接双击 index.html 来使用 API，也不要自行用普通静态服务器打开页面。

安装 Node.js 20 或更新版本，在本目录运行：

```powershell
node server.js
```

打开 <http://127.0.0.1:4173/>。主界面左侧依次是「继续游戏、关卡选择、成长档案、可选连接、更多设置」，导航下方有五段式通关进度条；右侧显示对应内容，默认封面含主行动按钮（开始第一关 / 继续当前关）与五关路线卡，点击任意一关直接进入。更多设置里可以开关音效，并选择游玩方式（娱乐／学习）和默认表达方式（自然语言／伪代码／C 代码）；进入关卡后这两项也能在右侧随时切换，改动会记在本机存档里。

## 部署到 Netlify

项目包含 `netlify.toml` 和 `netlify/functions/`。Netlify 构建时会运行 `node prepare-netlify.cjs`，只把游戏所需文件复制到 `dist`，并把 `/api/config`、`/api/test`、`/api/propose` 分别交给独立函数入口。请使用 Git 连接或 Netlify CLI 部署整个项目目录；只拖放静态 HTML 文件不会部署函数。

Windows 可以直接双击“部署到Netlify.cmd”。首次运行时按提示登录 Netlify，并选择已有站点 `incomparable-yeot-02251a`；之后脚本会构建并发布生产版本。也可以在项目目录手动执行：

```powershell
npx netlify-cli link
npx netlify-cli deploy --prod --build
```

线上页面填写的模型地址、名称和密钥只保存在当前页面的 JavaScript 内存中，每次测试或对话时通过 HTTPS 发送给同站点的 Netlify Function，再由函数请求模型服务。密钥不会写入 localStorage、游戏存档、源代码或接口响应；刷新或关闭页面后需要重新填写。

## 三种难度

- **自然语言**：用中文写下对象、动作、路线、循环或颜色条件。内置解析器只识别有限表达；失败信息会提示缺少的要素。
- **伪代码**：修改关卡给出的模板，逐行写清顺序、结束条件和分支。系统指出第一处无法识别的行。
- **C 代码**：引用 `workshop.h`，调用 `crystal_count()`、`crystal_color(id)` 和 `deliver(id, RED/BLUE)`。第一次运行时，浏览器会按需下载约 110 MB 的 Wasmer Clang 工具链。编译在常驻的编译 Worker 中完成，编译产物交给一次性运行 Worker 执行，因此超时中止只结束那一次运行，工具链保持可用。动作交由游戏引擎验证；网络或浏览器不支持时仍可玩前两种难度。

地图为 11 × 8，左上角坐标 (0, 0)，晶体按关卡数据从 0 编号。`deliver` 负责沿合法路线搬运指定晶体。源码、动作数和执行时间有限制。编译成功但没有完成任务也不会通关。

## 可选 AI 对话

主界面“可选连接 → API 设置”可填写兼容 Chat Completions 的地址、模型名称与密钥。直接点击“保存并测试”即可测试当前填写的内容。支持填写完整接口，或填写域名、`/v1` 基础地址并自动补全。配置只在当前本机 Node 进程内存中，接口不回传密钥，网页存档也不保存密钥。关闭服务后需要重新输入；配置过的同一家服务可留空密钥以沿用原值。

DeepSeek 可填写 `https://api.deepseek.com`、模型 `deepseek-chat` 及自己的密钥。401/403、地址错误、额度不足和连接超时会给出对应说明。通过 `file://` 双击网页不能连接模型，请使用上面的本机服务地址。

也可在启动服务前设置环境变量：

```powershell
$env:RULES_AI_URL = 'https://你的服务地址/v1/chat/completions'
$env:RULES_AI_MODEL = '模型名称'
$env:RULES_AI_KEY = '密钥'
node server.js
```

自然语言关卡中的“对话式规则助手”可直接在未配置 API 时使用本地识别；配置模型后优先使用 AI，故障时回退到本地识别。两种方式都先展示规则，玩家确认后才执行。支持连续补充策略，例如先说“把它带到右边的机器”，再说“绕开墙壁”。本地识别是有限规则解析，未识别的内容会指出缺少的对象、动作或目的地。

离线表达示例：第一关“把红色的水晶运到红色炉子，避开墙壁”；第二关“把所有东西搬到右边炉子，沿安全路线走”；第三关“重复搬运所有晶体，放到同色发电炉，绕过障碍”。不写绕行策略会按直接路线尝试，遇到障碍后可继续修改。API 不可用时，本地自然语言、伪代码及提示仍能使用。服务仅监听 `127.0.0.1`。

## 成长记录与导出

每次尝试保存提交内容、规则快照、执行步数、结果和停止原因。每个“关卡 × 难度”首次完成发放一次积分和徽章；重复完成只增加运行记录。主界面的导出中心可按关卡生成 Markdown 草稿，或选择关卡合成成长总报告。已有手写内容不会被重新生成覆盖，新事实可选择追加。所有文档需要主动下载，不自动公开。

存档位于浏览器本地存储。旧版进度、100 XP、徽章和编辑过的文章会在读取时迁移。清除站点数据会删除浏览器内的进度与文章，请及时下载需要保留的文档。

## 验证

```powershell
node --test
```

测试覆盖五关的规则与胜负判定、存档迁移、奖励、文档生成和本机 API 配置。

浏览器端检查需要先启动本机服务，再运行（Edge 路径写在脚本开头）：

```powershell
node e2e-check.cjs     # 主界面、三关流程、存档迁移、导出、AI 确认与回退、桌面/手机布局
node c-integration.cjs # 真实 Clang：三关通关、编译错误、无效投递、无限循环中止
```

C 集成测试首次运行会下载工具链，耗时取决于网络。
