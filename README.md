# 规则之外 · 能源工坊

纯本地的「规则编程」教学小游戏：玩家用**自然语言 / 伪代码 / C 代码**三种表达方式写规则，指挥地图角色完成搬运任务。三种表达方式最终都编译成同一份确定性规则程序（RuleProgram v2），由同一个本地引擎执行与判定胜负——AI 与模型不能直接改地图、不能判定通关。

零 npm 依赖、零构建步骤，克隆即玩。

## 五个关卡 · 两个章节

| # | 关卡 | 知识点 | 场景主题 |
|---|---|---|---|
| 1 | 第一颗能源核心 | 顺序 | 能源工坊 |
| 2 | 自动搬运系统 | 循环 | 能源工坊 |
| 3 | 颜色分拣工坊 | 条件 | 能源工坊 |
| 4 | 古籍档案馆 | 数组与遍历 | 档案馆（蓝紫主题） |
| 5 | 秘方蒸馏所 | 函数（def/call） | 蒸馏所（紫罗兰主题） |

章节与关卡在「关卡选择」里二级展开；每关有三种表达方式，首次完成各发一次 XP 与能力徽章（共 15 枚）。

## 启动

安装 Node.js 20 或更新版本，在本目录运行：

```powershell
node server.js
```

打开 <http://127.0.0.1:4173/>。主界面左侧依次是「继续游戏、关卡选择、成长档案、可选连接、更多设置」，导航下方是通关进度条；右侧封面有主行动按钮与按章节分行的学习路线。关卡内右上角「⚙ 设置」可随时切换游玩方式（娱乐/学习）与表达方式；AI 对话以右下角小窗进行；语音输入在编辑框右下角的圆形按钮。

**必须通过这个服务打开**：C 难度依赖服务下发的 COOP/COEP 头（`crossOriginIsolated`），AI 接口也挂在它上面，服务只监听 `127.0.0.1:4173`。

## 三种表达方式

- **自然语言**：用中文写下对象、动作、路线、循环或颜色条件。内置解析器只识别有限表达；失败信息会提示缺少的要素。
- **伪代码**：修改关卡给出的题材化模板（邮局说包裹、档案馆说卷宗），逐行写清顺序、结束条件和分支。系统指出第一处无法识别的行。
- **C 代码**：引用 `workshop.h`，调用 `crystal_count()`、`crystal_color(id)` 和 `deliver(id, RED/BLUE)`。第一次运行时浏览器按需下载约 110 MB 的 Wasmer Clang 工具链并缓存；编译在常驻 Worker 完成，运行交给一次性 Worker，超时强制终止。运行前「执行反馈」上方会给出本关对象清单（编号与坐标）。动作交由同一引擎校验；网络或浏览器不支持时仍可玩前两种。

地图 11 × 8，左上角 (0, 0)，晶体按关卡数据从 0 编号；第四关强制按编号递增投递。源码 ≤ 16000 字符、动作 ≤ 100 条、运行 ≤ 10 秒。

## 成长档案与成就

- **当前进度**：XP 进度条（每关 自然语言 100 / 伪代码 80 / C 120，总上限 1500）、统计磁贴、15 枚能力徽章网格。
- **整体成就**：普通成就 6 枚随主线解锁（首关、章节毕业、C 语言之路、五关全通、三语者、全收集）；彩蛋成就 5 枚记录特殊经历（越挫越勇、撞墙之后、AI 搭档、开口说话、深夜工坊），锁定时只显示线索。
- 每次尝试保存提交内容、规则快照、步数与结果；导出中心按关卡生成 Markdown 或合成成长总报告，手写内容永不被覆盖，支持下载 `.md`。

存档在浏览器本地存储（键 `beyond-rules-save-v3`，含旧版迁移）；清除站点数据会删除进度与文章，请及时下载需要保留的文档。

## 可选 AI 对话

主界面「可选连接」提供常用模型模板（OpenAI / DeepSeek / 智谱 / Kimi / 通义），点击预填地址与模型名；也可在「API 设置」手填兼容 Chat Completions 的完整地址、模型与密钥并测试连接。配置只保存在当前本机 Node 进程内存，接口不回传密钥，网页存档也不保存密钥。也可用环境变量 `RULES_AI_URL` / `RULES_AI_MODEL` / `RULES_AI_KEY` 启动。AI 提议的规则先展示预览，玩家确认后才交给本地引擎执行；API 不可用时本地玩法全部可用。

## 验证

```powershell
node --test              # 引擎五关×三难度、章节、成就、存档迁移、导出、AI 配置
node e2e-check.cjs       # 浏览器回归 56 项（需先启动服务）
node c-integration.cjs   # 真实 Clang 回归 9 项（首次下载 ~110MB 工具链）
```

两个 `.cjs` 开头硬编码了 Playwright 模块路径与 Edge 可执行文件路径，换机器请改成实际路径，或删掉 `executablePath` 让 Playwright 用自带 Chromium。

## 架构一览

| 文件 | 层 | 职责 |
|---|---|---|
| `engine.js` | 引擎（无 DOM） | levels/themes/chapters 注册表、三种入口编译器、`validate`、`execute`（BFS 寻路 + 事件流），Node 与浏览器共用 |
| `growth.js` | 数据层 | 存档 v3、XP/徽章/成就发放、按需导出文章生成 |
| `app.js` | 表现层 | 全部 UI：章节导航、主题化地图与文案、编辑器、执行动画、音效、AI 小窗、导出中心、C 难度调度 |
| `c-worker.js` / `c-run-worker.js` | 隔离层 | 浏览器端 Clang→Wasm 编译 / 受限运行 |
| `server.js` | 服务层 | 静态文件 + COOP/COEP + AI 代理（Host/Origin 校验、密钥只在内存） |
| `style.css` | 表现层 | 深色主题皮肤 + 每关 `data-theme` 元素配色 |

主题系统：每关的名词（货物/设施/角色/量词）、图标、图例、报错文案都从 `engine.js` 的 `themes` 注册表取；伪代码解析前会把题材词归一化为基础词，报错时再映射回本关词汇显示。加新关卡只需按 `HANDOFF.md` 的 checklist 增量扩展。
