01 · 问题与机会

学习者缺少的，常常不是更多语法，而是把想法变成规则的过程。

01
入门门槛高

一开始就面对严格语法，容易把注意力耗在格式与报错上。

02
反馈不够直观

程序执行发生在抽象环境里，学习者很难看见“规则如何影响世界”。

03
自然语言与代码断层

会描述解决方案，不等于能把它逐步表达成可执行逻辑。

04
试错缺少沉淀

失败、修改与成功没有被保存为可回看的成长记录。

02 · 核心体验

玩家真正玩的，是一轮表达与修正。

目标不只是“得到正确答案”，而是看见自己的规则被执行，并根据真实结果完成下一次表达。

STEP 01

观察任务

从地图、对象与目标中，找出真正需要解决的问题。

STEP 02

写下规则

使用自然语言、伪代码或 C 代码表达自己的策略。

STEP 03

看见执行

角色逐步行动，地图和日志共同呈现执行过程。

STEP 04

修改再试

根据撞墙、遗漏或条件错误，重新组织自己的规则。

05 · 三种表达方式

不是三套游戏，而是同一个问题的三层表达。

{ 中文 }

自然语言

先用熟悉的语言说清思路；本地解析无需 API，AI 可选增强讨论与改写。

把所有晶体送到同色发电炉，绕开障碍
{ 伪代码 }

结构化表达

用顺序、循环和条件拆分策略，错误会定位到具体动作或条件。

重复 直到 没有晶体\n 如果 颜色 = 红色\n 投递到 红色炉
{ C }

真实代码

浏览器端编译为 WebAssembly，在独立 Worker 中受限运行并回放动作。

for (int i=0; i<n; i++) {\n deliver(i, RED);\n}

06 · AI 与系统边界

AI 帮助表达，本地引擎负责事实。

模型可以讨论策略、解释错误并提出结构化规则，但不能直接移动角色，也不能决定玩家是否通关。

INPUT

玩家表达

自然语言、伪代码或 C 代码；对话修改后先展示规则预览。

→
RULE PROGRAM

受限规则

解析、校验并限制动作数、执行时间、源码大小与可用函数。

→
LOCAL ENGINE

确定性执行

统一验证移动、投递和胜负，生成可回放的真实执行记录。

API 不可用时，自然语言本地识别、伪代码、提示与核心关卡仍可运行。

07 · 功能亮点

把一次通关，变成可以带走的成长。

01 · 双模式

娱乐与学习共用进度

娱乐模式聚焦任务与结果；学习模式增加表达要点和逐级提示，切换不重置关卡。

02 · 真实记录

每次尝试都有上下文

保存提交内容、规则快照、执行步数、结果与失败原因，奖励只在首次完成时发放。

03 · 成长档案

XP、徽章与成就

按“关卡 × 表达方式”记录成长，鼓励玩家用不同方式重新理解同一个问题。

04 · 主动导出

从运行事实生成作品

按关卡生成文章或组合成长总报告；玩家可编辑并下载 Markdown，手写内容不会被覆盖。

08 · 技术栈与运行

轻量、透明、本机优先。

原型无需前端框架与构建工具，核心玩法不依赖云端账号或数据库。

线上演示：incomparable-yeot-02251a.netlify.app
本机运行：双击「启动游戏.cmd」
两种入口独立使用，无需同时启动
Node.js 20+桌面 / 手机适配浏览器本地存档测试覆盖核心闭环
界面层原生 HTML、CSS、JavaScript，响应式布局与无框架交互。
游戏引擎共享 RuleProgram、规则校验、确定性执行与地图回放。
服务层本机使用 Node.js；线上使用 Netlify Function 转发兼容 Chat Completions 的请求。
C 运行环境Wasmer Clang 按需加载，编译为 WebAssembly 后在独立 Worker 中运行。
数据与隐私进度保存在浏览器；密钥只驻留本机进程或线上页面内存，不写入游戏存档。
服务兼容可连接 DeepSeek、OpenAI、智谱、Kimi、通义千问等兼容接口。
